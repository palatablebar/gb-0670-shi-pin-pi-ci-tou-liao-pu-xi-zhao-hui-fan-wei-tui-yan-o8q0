# 台账字段

| 字段 | 定义 | 约束 |
|---|---|---|
| event_id | 投料事件编号 | 字符串保留前导零、大整数 |
| from_lot | 来源批次 | 原料用 R- 前缀；其余须有产出记录 |
| to_lot | 目标批次 | 同一目标共享产出与损耗定义 |
| quantity / unit | 本次投料数量与单位 | Decimal，支持kg、g、t、千克、克 |
| output_kg / loss_kg | 目标批总产出与损耗 | 同批不能冲突，两项非负 |
| status | 事件状态 | active有效；void撤回 |
| revision | 事件版本 | 正整数，最高版为准 |
| note | 原始备注 | 允许引号内换行 |

CSV字段顺序固定，包含UTF-8 BOM与GB18030回退。空值哨兵为：空串、-、N/A、NULL、未知。必要数量缺失不作零。单据时间取运行清单UTC时间；台账事件按版本裁决，本项目不推断未提供的发生时间。

所有输出数量用十进制字符串，标准单位kg，不经过浮点计算。图边是完整投料事件，存在同端点不同事件时各计一笔。数量必须严格大于零，不能以负向事件抵扣；撤回应通过更高revision的void事件表达。

召回起点为最多30个批次；未知起点列于unknown_seeds。召回输出lot、path、lines、depth和source。每个批次保留一条确定性最短证据路径。撤回、冲突、孤儿和物料不平衡的边不参与传播。

记录数分母仅含业务行。原因码表在app/reasons.py，隔离包含物理起始行号、原值与原因。清单摘要包含原始字节sha256、规则版本、参数、耗时和UTC时间。幂等键包含原始字节摘要、规则版及排序去重后的召回起点。人工复核版本采用乐观锁。

输入数量绝对值不超过10^12，最多6位小数；极端指数或精度超限返回BAD_DECIMAL并进入隔离，避免溢出。

## 修订裁决（部分重发）

供应商追加的修订可能只重发部分事件。系统不臆断未出现旧行的效力，登记时必须显式给出模式：

| 模式 | 未出现旧行待遇 | 召回后果 |
|---|---|---|
| `pending`（默认） | 保留在传播图，逐事件标`UNMENTIONED_PENDING` | 仅靠未现旧行到达的成品判`review`待核查 |
| `retain` | 显式沿用，视为已确认 | 成品路径仍可确认，判`keep`保留 |
| `withdraw` | 退出传播图，标`UNMENTIONED_WITHDRAWN` | 不可达成品判`remove`移除，已撤销批次不进清单 |

修订事件的`revision`必须严格高于该事件在基线中的最高版本，且`event_id`须在基线存在；否则分别记`AMEND_STALE_REVISION`、`AMEND_UNKNOWN_EVENT`，该行不参与合并。基线全部原始行与修订新行逐行合并后，沿用同一张契约/谱系/质量规则裁决，原始行不删除。

末端成品三态：`KEEP`（修订后仍可达且证据路径全部可确认）、`REMOVE`（修订后不可达，或withdraw模式下路径不可确认）、`REVIEW`（pending模式下仍依赖未现旧行，不可自证）。每个结论附`in_baseline_recall`、`in_amended_recall`、`confirmed_path`、最短证据`path`与原始`lines`，以及`evidence_source`（amended当前路径 / baseline旧结论回退）。被撤回而从图中消失的成品仍在裁决清单中给出`REMOVE`，并以基线旧路径作为复核证据。

修订幂等键由基线运行号、基线sha256、修订字节sha256、规则版、模式与排序去重后的起点派生；同一份修订重复登记只返回既有记录。修订独立存入`amendments`表，写入为单事务，异常随连接回滚；基线`runs`记录与原始字节始终不变。
